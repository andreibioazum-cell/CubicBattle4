# Новый Firebase для Cubic Battle (онлайн без комнат)

Игра **не ставит Android/iOS SDK**. Никакого приложения в Firebase создавать не нужно.
Нужна только **Realtime Database** и её URL. Клиент ходит туда обычным HTTPS REST.

## 1. Создать проект

1. Открой [https://console.firebase.google.com](https://console.firebase.google.com)
2. **Add project** / **Создать проект**
3. Имя любое, например `cubic-battle`
4. Google Analytics можно выключить
5. Дождись создания

**Платформу (Android / iOS / Web) не добавляй.** Кнопка «Add app» не нужна.

## 2. Включить Realtime Database

1. В меню слева: **Build → Realtime Database**
2. **Create Database**
3. Регион:
   - `europe-west1` — ближе к Европе/СНГ
   - или `us-central1` — дефолт США
4. На шаге правил выбери **Start in test mode** (на 30 дней открыто).
   Потом сразу поставь правила ниже.

Это должна быть **Realtime Database**, не Firestore.

## 3. Правила

Realtime Database → вкладка **Rules** → вставь и Publish:

```json
{
  "rules": {
    "rooms": {
      "main": {
        ".read": true,
        ".write": true
      }
    },
    "accounts": {
      "$nick": {
        ".read": true,
        ".write": "newData.exists()",
        "$field": {
          ".validate": "newData.isString() ? newData.val().length <= 80 : newData.isNumber()"
        }
      }
    }
  }
}
```

До 4 игроков в одной папке `rooms/main`. Клиент сам занимает первый свободный
слот (`players/0` ... `players/3`), поэтому экран ожидания не нужен.

Для отладки можно временно полностью открыть:

```json
{
  "rules": {
    ".read": true,
    ".write": true
  }
}
```

Не оставляй так навсегда: любой, кто знает URL, сможет стереть базу.

## 4а. Аккаунты: ник и пароль

Перед игрой (кнопка «Играть» или «Онлайн») игра просит ввести **ник** и
**пароль**. Если такого ника ещё нет — аккаунт создаётся, если есть —
проверяется пароль.

Как это устроено:

- Аккаунты лежат в `accounts/<ник>/`:

```
accounts/
  vasya/
    salt    — случайные 16 hex-символов (соль)
    hash    — SHA-256 от "соль:пароль" (64 hex)
    created — время создания
```

- **Пароль нигде не хранится и не передаётся в открытом виде** — в базу
  попадает только хеш. Даже если база утечёт, пароль из хеша не достать.
- **Один и тот же ник + другой пароль = вход запрещён.** Клиент при входе
  берёт `salt` аккаунта, считает `SHA-256(salt:введённый пароль)` и сверяет с
  `hash` из базы. Не совпало → «Неверный пароль».
- **Регистрация атомарная**: новый аккаунт создаётся условным запросом
  (`PUT` с заголовком `if-match: null`). Если два человека одновременно
  регистрируют один ник — создастся только один аккаунт, второй получит отказ
  и попробует войти как в существующий (неверный пароль → отказ).
- **Сессия запоминается**: после успешного входа ник и хеш сохраняются в
  файл приложения (`auth.dat`). При следующем запуске игра восстанавливает
  вход и в фоне проверяет, что хеш в базе не изменился; если пароль
  аккаунта сменился — сессия сбрасывается и игра снова просит пароль.
- Ник — только латиница/цифры/`_`, 3–16 символов; пароль — от 4 символов.

Правила выше дополнительно защищают аккаунты: удалить аккаунт нельзя
(`".write": "newData.exists()"` блокирует `DELETE`), а поля `salt`/`hash`
обязаны быть строками разумной длины.

> **Важно про открытые правила.** Если база полностью открыта
> (`.read/.write: true` на всё), злоумышленник с доступом на запись
> теоретически может перезаписать `hash` чужого аккаунта своим. Пароль он при
> этом всё равно не узнает (в базе только хеши), но аккаунт может испортить.
> Используй правила из этого раздела — они закрывают удаление; для полной
> защиты от перезаписи нужен Firebase Auth с секретным ключом (в этой игре
> SDK не используется, поэтому защита — хеши + атомарная регистрация).

## 5. Скопировать URL

Вкладка **Data**. Сверху адрес вида:

```
https://ИМЯ-проекта-default-rtdb.europe-west1.firebasedatabase.app
```

или

```
https://ИМЯ-проекта-default-rtdb.firebaseio.com
```

Без слэша в конце, без `.json`.

Вставь его в `game/config.ds`:

```
str FIREBASE="https://ИМЯ-проекта-default-rtdb.europe-west1.firebasedatabase.app", ROOM="main"
```

Пересобери игру.

## 6. Как это выглядит в базе

После подключения игроков в онлайне:

```
rooms/
  main/
    players/
      0/  uid, nick, x, y, angle, hp, alive, seq
      1/  ...
      ...

    bullets/
      0/  x, y, dx, dy, active, shot, tr
      1/  ...
      ...

    chat/
      <ключ>/  uid, nick, text, ts

accounts/
  <ник>/
    salt, hash, created

```

`x`, `y` — точка удара, `dx`, `dy` — направление (вправо/влево), `active` — идёт ли
удар, `shot` — счётчик ударов, `tr` — время с начала удара. Пули больше нет:
клиент публикует событие удара, соперники показывают спрайт `ordinary_punch.png`
на ~0.2 с и получают урон, если стоят в хитбоксе — широком (90px) и недлинном
(70px вперёд от бьющего).

Экрана ожидания больше нет: как только клиент занял слот, им можно сразу
двигаться и бить. Остальные игроки подтягиваются в ту же комнату по мере
подключения. Если все 4 слота заняты, новый клиент ждёт выхода или захватывает
слот, который молчит ~5 секунд.

## 7. Частые ошибки

| Симптом | Что проверить |
|---|---|
| «Нет соединения» | URL без опечаток, https, регион совпадает с базой |
| Не видно других игроков | Оба телефона на одном URL; правила разрешают write; подождите до 0.5 секунды на синхронизацию |
| Permission denied в логах | Правила не опубликованы или путь не `rooms/main` |
| Создал Firestore | Удали, создай именно Realtime Database |
| «Неверный пароль» у своего ника | Пароль не совпадает с тем, что был при регистрации этого ника (пароль не восстанавливается — только новый ник) |
| Вход долго «Подключение...» | База недоступна или правила закрывают `accounts` (нужен `.read` на `accounts`) |
| Ник не виден над головой | Правила должны разрешать чтение `rooms/main`; ник вводится при входе в аккаунт |
