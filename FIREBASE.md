# Новый Firebase для Cubic Battle (онлайн без комнат)

Игра **не ставит Android/iOS SDK**. Никакого приложения в Firebase создавать не нужно.
Нужна только **Realtime Database** и её URL. Клиент ходит туда обычным HTTPS REST.

## 1. Создать проект

1. Открой [https://console.firebase.google.com](https://console.firebase.google.com)
2. **Add project** / **Создать проект**
3. Имя любое, например `cubic-battle`
4. Google Analytics можно выключить
5. Дождись создания

**Платформу (Android / iOS / Web) не добавляй.** Кнопка «Add app» не нужна.

## 2. Включить Realtime Database

1. В меню слева: **Build → Realtime Database**
2. **Create Database**
3. Регион:
   - `europe-west1` — ближе к Европе/СНГ
   - или `us-central1` — дефолт США
4. На шаге правил выбери **Start in test mode** (на 30 дней открыто).
   Потом сразу поставь правила ниже.

Это должна быть **Realtime Database**, не Firestore.

## 3. Правила

Realtime Database → вкладка **Rules** → вставь **целиком** содержимое файла
[`firebase.rules.json`](firebase.rules.json) из репозитория и нажми **Publish**.
Это же — здесь:

```json
{
  "rules": {
    ".read": false,
    ".write": false,

    "rooms": {
      ".read": false,
      ".write": false,
      "$room": {
        ".read": true,
        ".write": true,

        "players": {
          ".read": true,
          ".write": true,
          "$slot": {
            ".read": true,
            ".write": true,
            ".validate": "$slot.matches(/^[0-3]$/)"
          }
        },

        "bullets": {
          ".read": true,
          ".write": true,
          "$slot": {
            ".read": true,
            ".write": true,
            ".validate": "$slot.matches(/^[0-3]$/)"
          }
        },

        "chat": {
          ".read": true,
          ".write": true,
          ".indexOn": ".key",
          "$msg": { ".read": true, ".write": true }
        }
      }
    }
  }
}
```

### Почему друг видел «Нет соединения» и что исправлено

Старые правила разрешали только `rooms/main` и `accounts/$nick`, и этого не
хватало в трёх случаях:

1. **Test mode истёк.** «Start in test mode» открывает базу на 30 дней, потом
   Firebase сам ставит `"read": false, ".write": false` на весь корень — у
   всех, кто зашёл позже, всё падает с `401 Permission denied`. Новые правила
   постоянные, срок у них не истекает.
2. **Чтение всей комнаты одним запросом.** Клиент делает `GET /rooms/main.json`
   и `GET /rooms/main/chat.json?orderBy="$key"&limitToLast=20`. Правило,
   висевшее только на `rooms/main`, работало, но любое переименование комнаты
   (`ROOM` в `config.ds`) сразу ломало доступ. Теперь правило на `$room` —
   работает для любого имени комнаты.
3. **Запрос чата с `orderBy="$key"`.** Без `".indexOn": ".key"` Firebase на
   больших чатах отвечает предупреждением/ошибкой индекса. Индекс добавлен.

Плюс сетевые правки самого клиента (`net.c`), из-за которых у второго игрока
появлялось «Нет соединения»:

1. **Таймауты HTTP 2 с → 4 с.** На мобильном интернете короткие всплески
   задержки (DNS, переподключение к вышке) раньше выглядели как обрыв сети:
   2-3 случайных таймаута подряд рисовали «Нет соединения». Теперь ошибка
   показывается только после 6 неудач подряд, а в фоне игра всё время
   переподключается («Переподключение...» на экране).
2. **«Призрачные» слоты захватываются за 6 с вместо 12.** Если приложение
   убили без выхода из онлайна, его слот оставался в базе; перезашедший игрок
   ждал почти полминуты. Теперь чужой слот, который молчит 6 секунд,
   занимается сразу.
3. **Экран входа больше не ходит в сеть.** Раньше «Нет соединения» могло
   появиться ещё до боя — на экране логина. Теперь вход это только ник,
   который проверяется и сохраняется на устройстве: этот класс сбоев исчез.

Правила проверяют формат данных, но **не требуют аутентификации Firebase Auth**:
игра ходит в базу обычным HTTPS REST без токена. Если поставить `auth != null`,
игра перестанет подключаться у всех.

До 4 игроков в одной папке `rooms/main`. Клиент сам занимает первый свободный
слот (`players/0` ... `players/3`), поэтому экран ожидания не нужен.

Для отладки можно временно полностью открыть:

```json
{
  "rules": {
    ".read": true,
    ".write": true
  }
}
```

Не оставляй так навсегда: любой, кто знает URL, сможет стереть базу.

## 4. Вход в онлайн: только ник

Регистрации больше нет. Нажал «Онлайн» без сохранённого ника — игра открывает
экран «Введите ник»: одно поле и кнопка «Играть».

- **Ник 3–16 символов** (латиница, цифры, `_`). Не подходит — «Неверный ник»,
  запрос в сеть не уходит.
- Никаких паролей и аккаунтов в базе: в Firebase пишутся только слоты комнаты
  и чат. Два игрока могут случайно взять один ник — они всё равно различаются
  по техническому `uid`.
- Ник сохраняется в файл `auth.dat` (внутренняя память приложения), при
  следующем запуске вход происходит автоматически, «Онлайн» пускает сразу.
- **Ник показывается над головой игрока** (своего и соперников) и в чате.
- Кнопка «Аккаунт» в лобби открывает тот же экран — ник можно сменить.

Код входа (`net_set_nick`, `net_autologin`) живёт в `net.c`, экран — в
`game/menu.ds`.

## 5. Скопировать URL

Вкладка **Data**. Сверху адрес вида:

```
https://ИМЯ-проекта-default-rtdb.europe-west1.firebasedatabase.app
```

или

```
https://ИМЯ-проекта-default-rtdb.firebaseio.com
```

Без слэша в конце, без `.json`.

Вставь его в `game/config.ds`:

```
str FIREBASE="https://ИМЯ-проекта-default-rtdb.europe-west1.firebasedatabase.app", ROOM="main"
```

Пересобери игру.

## 6. Как это выглядит в базе

После подключения игроков в онлайне:

```
rooms/
  main/
    players/
      0/  uid, nick, x, y, angle, hp, alive, seq
      1/  ...
      ...

    bullets/
      0/  x, y, dx, dy, active, shot, tr
      1/  ...
      ...

    chat/
      <ключ>/  uid, nick, text, ts
```

`uid` — технический идентификатор устройства (16 hex-символов). `nick` — ник
игрока: он публикуется в комнату и **показывается над головой** игрока и в чате.

`x`, `y` — точка удара, `dx`, `dy` — направление (вправо/влево), `active` — идёт ли
удар, `shot` — счётчик ударов, `tr` — время с начала удара. Пули больше нет:
клиент публикует событие удара, соперники показывают спрайт `ordinary_punch.png`
на ~0.2 с и получают урон, если стоят в хитбоксе — широком (104px) и недлинном
(104px вперёд от бьющего). У соперников (и у бота в соло) во время замаха и
удара рисуется красный полупрозрачный прицел — видно, куда придётся удар.

Экрана ожидания больше нет: как только клиент занял слот, им можно сразу
двигаться и бить. Если все 4 слота заняты, новый клиент ждёт выхода или
захватывает слот, который молчит ~6 секунд.

## 7. Частые ошибки

| Симптом | Что проверить |
|---|---|
| «Нет соединения» | URL без опечаток, https, регион совпадает с базой; игра сама переподключается — подожди пару секунд |
| Не видно других игроков | Оба телефона на одном URL; правила разрешают write; подождите до 0.5 секунды на синхронизацию |
| Permission denied в логах | Правила не опубликованы или путь не `rooms/...` |
| Создал Firestore | Удали, создай именно Realtime Database |
| Ник не виден над головой | Правила должны разрешать чтение `rooms/main`; ник задаётся на экране «Введите ник» |
