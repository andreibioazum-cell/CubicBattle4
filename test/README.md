# Головной тест-стенд (Linux, без Android)

Позволяет прогнать настоящий скрипт игры (init/update/draw/touch) с реальными
сокетами и потоками против фейкового Firebase-сервера. Нужен, чтобы ловить
вылеты/зависания онлайна без телефона.

## Запуск

```sh
python3 test/fake_firebase.py 18765 &   # фейковый Firebase (перезапускать перед каждым прогоном:
                                        # сценарий меняет данные комнаты)
./test/build_test.sh                     # собирает test/game_test (ASAN+UBSAN)
rm -f auth.dat                           # чистый старт без сессии
./test/game_test                         # гоняет весь сценарий
```

Сценарий в `test/main_linux.c` (ник на каждый запуск уникальный):

0. **Предупреждение об эпилепсии**: при запуске `warn_open == 1`, полный чёрный
   экран с красным WARNING/ВНИМАНИЕ на двух языках, без кнопки OK. Тап не
   закрывает его и не проходит в меню. Через 2,5 с плюс плавное затухание
   `warn_open` становится 0.
1. «Онлайн» без сохранённого ника открывает экран «Введите ник».
2. **Пустой ник** отклоняется на месте, без запроса в сеть; ник из одного
   символа разрешён.
3. **Ник с запрещёнными символами** отклоняется так же.
4. Корректный ник и непустой пароль — сразу в онлайн: слот занят, `NET_PLAYING`.
   Вход идёт через фейковый Firebase Auth (см. ниже «Защищённый режим»).
5. Чат: открыть (на весь экран) → написать → отправить → лишние старые
   сообщения удаляются → закрыть кнопкой размера «Играть».
   Чат открывается тапом в правый нижний угол кнопки: она теперь размером
   с «Назад» (`btn_w × btn_h`), старая маленькая 140×48 туда не доставала.
   Отдельно проверяется удаление в поле ввода: `Q` + Backspace + `qwerty`
   даёт ровно `qwerty` (стёртое не «воскресает» как `Qqwerty`), а
   `keyboard_clear` оставляет поле пустым.
5b. **Защищённый режим:** по `/__stats.json` фейкового сервера проверяется,
   что регистрация в Firebase Auth состоялась (`sign_up ≥ 1`), а к базе
   клиент ходил только с `?auth=` (`rtdb_no_auth == 0`). Неверный пароль (8)
   при этом честно отклоняется сервером (`INVALID_PASSWORD`).
6. **Сетевой удар не теряется:** у соперника меняется только постоянный
   счётчик `punch` (без короткого `active=1`), а игра всё равно запускает
   анимацию и хитбокс. Цвет пикселя внутри полосы проверяется отдельно: слой
   должен одинаково затемнять R, G и B, то есть быть чёрным, а не красным.
7. **Вышедший игрок удаляется:** после удаления его слота список `remotes`
   пустеет вместе с незавершённым ударом.
8. Выход из онлайна в лобби.
9. Ник записан в `auth.dat`.
10. Соло-бой работает; бот успевает несколько атак, а его перезарядка каждый
    раз случайная и лежит в `enemy_cooldown_min..enemy_cooldown_max`.
    **След врага**: игрок в этом тесте стоит на месте, поэтому любая живая
    пыль — шлейф бота; кадров с пылью за 15 секунд боя должно быть ≥ 30.
11. Ивенты работают только в онлайне: при `/event = 2` в онлайне включается
    снегопад (`event_mode == 2`), а выход из онлайна сбрасывает ивент.
    Соло-бой (оффлайн) ивент игнорирует: `event_mode` остаётся нулём, даже
    если сервер в это время переключает ивент.
12. Вкладка «Классы»: без кубков Азум не выбирается; за 50 кубков покупается
    и сохраняется в `progress.dat`. Под каждой карточкой видны и покупаются
    только уровни 1–3; ветки Азумa и Деда Мороза независимы. В соло первое
    обнуление HP поднимает игрока, второе — уже поражение (кубки за поражение
    не дают).
    Класс соперника в онлайне читается из поля `cls`.
    **Прайм-уровни и ауры**: кнопка «Прокачать прайм» трижды тратит кубки
    (20/30/40) и поднимает прайм-уровень Азума 1→2→3, на максимуме кнопка
    больше ничего не меняет; уровень сохраняется в `progress.dat`. В соло-бою
    вокруг игрока рисуется аура, цвет которой зависит от уровня: 1 — красное
    свечение, 2 — зелёное, 3 — жёлтое (дифференциальная проверка пикселей по
    доминирующему каналу).
13. Повторный вход в онлайн: сохранённый ник пропускает экран ника,
    слот занимается сразу. Победа (последний соперник вышел) начисляет все
    три валюты: 5 кубков, 3 леденца и 1 прайм; в таблице лидеров у каждого
    игрока справа видны его кубки (золотое число, без значка-кубка).
14. **Снежинка Деда Мороза в онлайне**: класс «Дед Мороз» покупается за
    леденцы, в онлайне видна фиолетовая кнопка суператаки (проверка пикселя),
    тап по ней сначала запускает «пустую» анимацию удара (замах без урона,
    без хитбокса и без публикации события удара), и только после неё летит
    снежинка (счётчик `snow` публикуется в сеть, снаряд долетает и взрывается).
    Чужая снежинка (событие от соперника, положенное на сервер напрямую)
    НЕ наносит урона — только замораживает игрока и рисует ледяной круг и взрыв.
15. **Новый баланс Деда Мороза в соло**: удар посохом снимает всего 0.25 HP,
    но отравляет врага (яд дискретный: тик раз в `santa_poison_tick_interval`
    секунд уроном `santa_poison_dps` + бонус уровня, вокруг врага голубой круг,
    потом яд кончается и HP замирает); через 0.4 с после ручного удара посох
    бьёт второй раз сам (один раз, яд при этом не обновляется). Снежинка имеет
    кулдаун ровно 3 секунды, замораживает врага и бьёт ровно на
    `santa_super_damage` HP.
16. **Слои отрисовки**: бой рисуется слоями «все тени -> хитбоксы ударов ->
    снаряды -> все персонажи». Полоса удара (своя и бота) обязана лежать
    выше тени, но ПОД спрайтами. Проверка дифференциальная: сравниваются
    кадры с полосой и без неё при одинаковых спрайтах — непрозрачные
    пиксели спрайта, накрытого полосой, совпадают только если полоса
    нарисована под спрайтом (на старом порядке совпадений 0).
17. **Бан работает по-настоящему**: вход под админом (`ADMIN_NICK`/`ADMIN_PASS`
    из config.ds), команда `ban BotRival` в чате → на сервере появляется
    `/bans/BotRival = true`, забаненный соперник пропадает из списка игроков, а
    его слот удаляется с сервера; если положить его обратно — он снова не виден.
    Дальше админ банит сам себя: клиент обязан пометить себя забаненным
    (`net_banned() == 1`), освободить слот и вернуться в меню с сообщением
    `tr_banned()`, а кнопка «Онлайн» после этого в онлайн не пускает. `unban`
    убирает запись с сервера, и ник снова заходит в онлайн и занимает слот.
    В комнате всё это время держится второй (не забаненный) соперник — иначе
    после кика врагов не остаётся, игра засчитывает победу и закрывает чат.
18. **Второй админ — те же права, своя подпись**: вход по паре
    `ADMIN2_NICK`/`ADMIN2_PASS` из `config.ds` даёт ровно те же команды: `event 2`
    из чата доходит до сервера (`/event = 2`, и именно тут проверяется, что
    `net_event_set` пишет скаляр через `PUT` — на `PATCH` Firebase отвечает
    «Patch requires a JSON object»), а ответ подписан ником вошедшего
    (`SNOW EVENT by qwertyuiopaj1234`), а не всегда главного админа. Дальше
    обычный игрок (`RegPlayer`) отправляет `event 2` и `ban RegTarget` — обе
    строки остаются текстом чата: `/event` не меняется, `/bans/RegTarget` не
    появляется.

Отдельно проверяется, что бот **поворачивается плавно**: за кадр угол меняется
не больше чем на `max(enemy_attack_turn_speed, enemy_face_max_speed) / 60`
радиан. На старом коде враг в начале замаха мгновенно доворачивался на игрока.

В конце `reset()` освобождает игровые объекты, поэтому ASAN завершает прогон
без «утечек» — любой ненулевой код выхода значит, что что-то сломалось.

Также проверено: при полностью «мёртвой» сети (сервер выключен) игра не
зависает — показывает «Нет соединения» + «Переподключение...», а в консоль
пишутся причины ошибок не чаще раза в 2 секунды.

`build_test.sh` временно подменяет URL Firebase в `game/config.ds` на
`http://127.0.0.1:18765`, генерирует `game/game.c`, собирает и затем
восстанавливает настоящий URL (config.ds и game.c возвращаются к реальному
Firebase).

Замечание: `game/game.c` — сгенерированный файл, в git не хранится.

## Защищённый режим в тестах

`build_test.sh` подставляет не только локальный URL, но и фиктивный
`FB_KEY="fake-key"`, поэтому весь прогон идёт через Firebase Auth: вход и
регистрация — через `/v1/accounts:signUp` и `/v1/accounts:signInWithPassword`
фейкового сервера, обновление токена — через `/v1/token`, а каждый запрос к
базе несёт `?auth=`. Счётчики запросов доступны тесту как `GET /__stats.json`.

Также прогон требует свежеподнятого `fake_firebase.py` (счётчики и комната
сбрасываются только при перезапуске сервера).
