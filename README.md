# Gig1.0 / DimScript — Android 10 only, без звёзд

## Что исправлено по оценке 6/10

**Слабые стороны были:**
- Ограниченный типаж (нет массивов, словарей, bool, enum)
- Минимальная stdlib (нет файлов, JSON, сети, таймеров)
- Синтаксис без преимуществ
- Привязка к одному движку (и кроссплатформенность была лишней)

**Исправления:**

### 1. Типы
- `bool` с `true`/`false` → `int` 1/0
- `arr` — динамический массив `num`: `arr_new()`, `arr_push()`, `arr_get()`, `arr_set()`, `arr_len()`, `arr_pop()`, `arr_clear()`, `arr_free()`
- `dict` — словарь `str -> num`: `dict_new()`, `dict_set()`, `dict_get()`, `dict_has()`, `dict_del()`, `dict_free()`
- `timer` — таймер: `timer_new()`, `timer_start()`, `timer_elapsed()`, `timer_reset()`, `timer_free()`
- `enum` — `enum State Lobby=0, Game, Menu end` создаёт константы

### 2. Стандартная библиотека
- Файлы: `file_read()`, `file_write()`, `file_exists()`, `file_del()`
- JSON: `json_get_str()`, `json_get_num()`, `json_get_bool()`
- Сеть: `http_get()`, `http_post()` + уже существующие `net_connect()` для Firebase
- Утилиты: `clamp()`, `lerp()`, `dist()`, `now()`, `ds_log()`
- Онлайн — одна общая комната `main` в Firebase Realtime Database, до 4 игроков без экрана ожидания (см. `FIREBASE.md`)

### 3. Синтаксис проще и компактнее
- `;` — несколько операторов в строке: `x=0; y=0; hp=10`
- `,` — несколько переменных: `num x=0, y=0, size=30`
- Объекты в 3 строки: `object Player` / `num x=0, y=0...` / `end`
- `then` / `do` и `:` в конце `if`/`loop` — более читаемо
- `c` — inline C: `c printf("hi\n");` / `c ds_log("fire");`
- Код игры сжат с 853 до 186 строк (-78%), 6 файлов без цифр

### 4. Платформа — теперь только Android 10
По запросу убрана кроссплатформенность:
- Только `arm64-v8a` + `armeabi-v7a`
- Только Android 10 API 29 (`minSdkVersion 29`, `targetSdkVersion 29`)
- `runtime.h`, `graphics.c`, `main.c`, `net.c` — только Android, без desktop fallback и без `#ifdef __ANDROID__` веток
- Звёзды полностью удалены: нет `init_stars`, `update_stars`, `draw_stars` ни в рантайме, ни в компиляторе

### 5. Онлайн: меньше лага и ближний бой вместо пуль
- **Диагностика сети:** при сбоях в консоль пишется конкретная причина
  (код WinINet на ПК, текст исключения Java на Android, HTTP-статус), не
  чаще раза в 2 секунды — без спама.
- **Меньше лага и никаких «вылетов»:** таймауты HTTP сокращены до 2 с, а при
  выходе из онлайна — до 0.8 с: если Firebase недоступен, игра больше не
  зависает на секунды (раньше при «мёртвой» сети выход из онлайна блокировал
  поток до ~15 с и приложение убивалось системой — выглядело как вылет при
  заходе в онлайн). Слот при отключении освобождается сразу.
- **Меньше лага:** `net.c` больше не делает последовательные HTTP-запросы на одном
  потоке. Запись (`PATCH` своего состояния) и чтение (`GET` комнаты) идут на двух
  параллельных потоках с интервалом 50 мс — обновления соперников приходят часто
  и не блокируют друг друга.
- **Удар вместо пули:** пуля не вылетает. Пока игрок держит кнопку атаки —
  показывается чёрный слегка прозрачный прицел-хитбокс, а сам удар происходит в момент, когда
  игрок отпускает кнопку (перестал целиться). Спрайт игрока на ~0.2 с меняется с
  `ordinary.png` на `ordinary_punch.png`, и весь этот кадр хитбокс ближнего боя
  активен: уменьшенный (`punch_width` = 58px, `punch_reach` = 58px) и повёрнутый
  по направлению игрока. Хитбокс врага также уменьшен и учитывает его угол вращения.
  Событие удара публикуется в Firebase как `(x, y, dx, active, shot)` — соперники
  показывают спрайт удара и получают урон, если стоят в хитбоксе.
- **Персонаж и одиночный бот:** игрок и бот теперь одного размера
  (`enemy_scale` поднят с 1 до 1.8 — враг больше не «мелкий»). Бот больше
  не наносит урон простым столкновением: он держит дистанцию, стрейфит, прогнозирует
  движение игрока, показывает читаемый замах, фиксирует направление удара, атакует
  один раз за окно попадания и восстанавливается перед следующим заходом. От его
  атаки можно увернуться; отладочная визуализация хитбокса врага скрыта.
- **Чат:** пока чат закрыт, сообщения поверх боя не показываются. В окне оставлены
  только «Закрыть», поле ввода и «Отправить» — кнопки прокрутки и постоянная кнопка
  клавиатуры убраны. Системная Android IME открывается только после нажатия на поле
  сообщения; настоящий `EditText`/`InputConnection` поддерживает Unicode-ввод.
  Enter отправляет сообщение.
- **Интерфейс:** подписи кнопок, подсказка поля сообщения и другие строки внутри
  элементов центрируются по фактическим границам глифов, без вертикального сдвига.
- **Консоль:** в настройках показывает все логи игры. Фон идеально чёрный,
  обычные логи — зелёным, ошибки (включая «текстура не загрузилась») — красным.

### 6. Языки интерфейса
- В настройках доступны English, Русский и 日本語.
- 日本語 — это **японский** язык (ниппонго), а не китайский: иероглифы
  (кандзи) в нём заимствованы из китайского, поэтому выглядят похоже.
  Добавлен как третий язык интерфейса вместе с английским и русским.
- На японский переведены меню, бой, результаты, сетевые статусы, чат и консоль.
- В шрифтовый атлас вшит весь набор символов игры: латиница, кириллица, вся
  хирагана и катакана, а также все кандзи из строк интерфейса — японские
  надписи и введённый игроком японский текст (чат) отрисовываются, а не
  «исчезают» из-за отсутствующих глифов.

### 7. Регистрация: без неё в онлайн не пустит
- Онлайн закрыт входом «Ник + пароль». Нажал «Онлайн» без входа — игра
  открывает экран аккаунта. Соло доступно без регистрации.
- На экране аккаунта два режима: **«Войти»** (ник + пароль) и
  **«Создать аккаунт»** (ник + пароль + **повтор пароля**). Если пароли не
  совпадают — «Пароли не совпадают», запрос даже не уходит в сеть.
- Ник 3–16 символов (латиница, цифры, `_`), пароль от 4 символов. Создание
  аккаунта атомарное (`if-match: null`): если ник уже занят — «Аккаунт уже
  существует», чужой аккаунт не перезаписывается.
- Вход: **одинаковый ник с другим паролем не пустит** («Неверный пароль»).
- Пароль не хранится: в базе только `salt` + SHA-256-хеш. Сессия сохраняется
  в `auth.dat`, при запуске — автовход. «Выйти» — справа сверху на экране
  аккаунта.
- **Ник показывается над головой игрока** (своего и соперников) и в чате.
- В японскую раскладку добавлены недостающие кандзи экрана аккаунта.

### 8. ПК (Windows): «Нет соединения» — теперь с причиной
- HTTP-ошибки WinINet пишутся в игровую консоль (Настройки → Консоль):
  код 12007 = DNS не находит хост, 12029 = не могу соединиться, 12038 =
  сертификат, 12002 = таймаут, 401 = правила Firebase запрещают доступ.
- Если системный прокси/антивирусный фильтр ломает сеть — игра
  автоматически повторяет запрос прямым соединением (без прокси).
- Если сервер не отдал ETag (WinINet на некоторых ПК), пустой слот теперь
  занимается и без `if-match` — раньше это выглядело как вечное
  «нет соединения».

## Структура

```
game/
├── config.ds    — все num/str через запятую (параметры удара: punch_*)
├── locale.ds    — английские, русские и японские строки интерфейса
├── entities.ds  — игровые объекты (Player/Enemy/Punch) и сетевые массивы
├── ui.ds        — кнопки, зона «Назад» и полосы HP
├── menu.ds      — лобби, режимы, настройки и консоль
├── chat.ds      — скрытый до открытия онлайн-чат с системной клавиатурой
├── battle.ds    — соло + синхронизированный онлайн Firebase (ИИ, прицел, удар, ники)
├── engine.ds    — переходы без вспышек, игровые хуки и логи загрузки текстур
```

Сеть — в `net.c`/`net.h`: подключение к Firebase, занятие слота, публикация
состояния (с ником), чат и вход по нику/паролю (SHA-256, атомарная
регистрация, автовход по сохранённой сессии).

Шрифт `game/assets/fonts/ChillRoundGothic_Heavy.ttf` обязателен — без него
текст в игре не отрисовывается вообще (атлас глифов строится из него).

## Сборка

```sh
python3 gen.py
```

NDK (Android 10):
```sh
aarch64-linux-android29-clang -O3 -shared game.c runtime.c main.c glue -landroid -llog -lm -o lib/arm64-v8a/libds_game.so
armv7a-linux-androideabi29-clang ... -o lib/armeabi-v7a/libds_game.so
aapt package -M AndroidManifest.xml -I android-29/android.jar -F apk
```

APK только для Android 10 arm64/arm32, без звёзд, без кроссплатформы.
